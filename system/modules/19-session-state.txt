# Session State

Use this module in any multi-persona session or whenever a mid-session mode switch occurs.

## Purpose

`SESSION_STATE.md` is a temporary, machine-readable file written and read by the active persona at every phase transition and mode switch. It preserves context across:
- Phase transitions within a session
- DISCUSS mode entry and exit
- Mid-session persona switches

!!! `SESSION_STATE.md` must be listed in `.gitignore`. It is never committed.

## File location

Always at repo root: `SESSION_STATE.md`

## Initialization

When `SESSION_STATE.md` is first required (phase transition, DISCUSS entry,
persona switch, or mode switch) and does not yet exist:

1. Create it from the template below with all fields set to their default values.
2. Verify that `.gitignore` contains `SESSION_STATE.md`. If not, append it and
   note the addition in the session log.
3. Do not commit `SESSION_STATE.md`. It is a temporary working artifact.

## Write rules

The active persona writes or overwrites `SESSION_STATE.md` at every:
- Phase transition
- DISCUSS entry or exit
- Persona switch
- Promotion of a discuss item

If the file does not exist, create it from scratch using the template below.

## Read rules

- Any incoming persona must read `SESSION_STATE.md` before emitting its first response.
- If the file is missing and the session has a prior context, go BLOCKED and request the state file.
- If the file is present but fields are missing, fill them from conversation context where unambiguous; otherwise go BLOCKED on the missing field.

## Target

## Backlog
<!-- Filled during BACKLOG phase (BabaScrumMaster, full mode only) -->

## Milestones
<!-- Declared during INTAKE -->

<!-- Filled during SPRINT phase (BabaScrumMaster, full mode only) -->

- To do: []

## Mid-session persona switch protocol

When the user explicitly requests a persona switch mid-session (e.g. "switch to BabaTester", "let BabaSensei look at this"):

1. Active persona writes current full state to `SESSION_STATE.md` including a new entry in `Persona Switch Log`
2. Active persona emits: `[PERSONA SWITCH: <from> -> <to>]` and a one-line state summary
3. Incoming persona reads `SESSION_STATE.md` in full
4. Incoming persona emits: `[PERSONA: <name>] [PHASE: <current_phase>]` and confirms restored context in one line
5. Incoming persona continues from the current phase — it does NOT restart

!!! A persona switch does not reset the phase.
!!! A persona switch does not clear findings, constraints, or open questions.
!!! If incoming persona cannot satisfy a hard constraint of the current phase, it goes BLOCKED.

## Cleanup rule

Delete `SESSION_STATE.md` when:
- Session concludes with a successful PATCH or explicit user close
- User says "close session", "end session", or "clean up"

Do not delete on FAILURE — preserve for post-mortem.
